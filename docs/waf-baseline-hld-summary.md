# Cloudflare Landing Zone: AppSec WAF baseline (source material for HLD)

Summary of the WAF baseline as implemented, for use when filling in the AppSec / WAF section of a High-Level Design. Written from the code at `main` @ `4ae43c7` (2026-10-19). Where this document and the code disagree, the code wins.

**Source of truth:**

- Layer: `deployment/layers/waf/`
  - Rule catalogue: `locals.waf.tf`
  - Assembly: `locals.tf`
  - Guards: `preflight.tf`
  - Platform defaults: `defaults.auto.tfvars`
- Module: `modules/waf/`
- Per-account config: `deployment/accounts/<account>/waf.tfvars`

The account values in section 6 are sample/placeholder data (RFC 5737 IPs, example.com).

## 1. Design model

- **One WAF policy per zone.** The `waf_policies` map binds each policy to a zone through `zone_key`. A zone with no policy gets no rulesets. A second policy on the same zone is rejected, because Cloudflare allows one entry-point ruleset per phase per zone.
- **Baseline catalogue.** Rules are named once in the platform catalogue and each policy opts in by name. The catalogue holds no customer data: trusted IPs, admin paths, countries, list names and HTML routes all come from variables. Platform defaults live in the layer's `defaults.auto.tfvars` and are overridden per account.
- **Tenant rules come after the baseline** in each phase.
- **Three zone entry-point rulesets.** Each one is created only when it has content:

| Phase | Default ruleset name | Contents, in evaluation order |
|---|---|---|
| `http_request_firewall_custom` | `Custom rules - <domain>` | 1. Bot traffic rules (search → agent → training) 2. Selected baseline custom rules 3. Tenant `custom_block_rules` |
| `http_ratelimit` | `Rate limiting - <domain>` | Baseline rate limits, then tenant rate limits. `cf.colo.id` is added automatically to every rule's characteristics (Cloudflare API error 20155) |
| `http_request_firewall_managed` | `Managed rules - <domain>` | 1. Baseline exceptions (skip) 2. Tenant exceptions 3. Baseline managed rulesets (execute) 4. Tenant managed rulesets |

- Cloudflare runs the phases in this order: custom rules, then rate limiting, then managed rules.
- Paid zones already have a Managed Rules entry point. Terraform adopts it with an `import` block (`imports.tf`) instead of creating a new one.
- Every rule label must be unique within its ruleset (enforced by a precondition).
- Coarse bot controls (Bot Fight Mode, Super Bot Fight Mode, `ai_bots_protection`) are not in this layer. They belong to the zones layer's `bot_management` setting.

## 2. Global parameters (effective platform defaults)

| Variable | Effective default | Purpose |
|---|---|---|
| `waf_trusted_ip_ranges` | `[]` (set per account) | Corporate egress/VPN ranges. Used by the admin rules and as the exclusion for the bot challenge |
| `waf_admin_paths` | `/admin`, `/administrator`, `/phpmyadmin`, `/wp-login.php`, `/wp-admin`, `/user/login`, `/user/password`, `/user/register` | Matched with `contains`. The variable's own default lists only 3 paths; `defaults.auto.tfvars` overrides it with these 8 |
| `waf_blocked_countries` | `[]` | ISO 3166-1 alpha-2 codes. Geoblocking is a per-customer regulatory decision |
| `waf_ip_blocklist_name` | `null` | Name of an account IP List created by the `lists` layer |
| `waf_managed_rules_action` | `null` (each rule keeps Cloudflare's shipped action) | Forces one action on every Cloudflare Managed rule. `log` gives a monitor-mode rollout |
| `waf_owasp_paranoia_level` | `1` | Paranoia levels above this are disabled by the category tag `paranoia-level-N` |
| `waf_owasp_score_threshold` | `40` (medium) | Cloudflare's scale: 60 = low, 40 = medium, 25 = high. A lower number is more aggressive |
| `waf_owasp_action` | `null` (Cloudflare default) | Action when the anomaly score crosses the threshold |
| `waf_html_submission_paths` | `[]` | Regexes, anchored `^(…)$` |
| `waf_html_submission_methods` | `["POST"]` | Only POST, PUT or PATCH allowed |
| `waf_html_submission_skip_rule_ids` | `[]` | Cloudflare Managed rule IDs to skip, taken from Security Events |
| `default_zone_tier` | `free` | Plan assumed when a zone has no `zone_tier` |
| `bot_traffic_min_tier` | `pro` | Lowest plan allowed to use `bot_traffic` |
| `managed_rules_min_tier` | **`enterprise`** | Lowest plan allowed to use managed rulesets. See issue 1 |

## 3. Rule catalogue

### 3.1 Bot traffic (generated by the module, top of the custom ruleset)

- **Input:** `bot_traffic = { search, agent, training }`. Each behaviour takes one of `allow`, `log`, `managed_challenge`, `js_challenge`, `challenge` or `block`.
- **Expression:** `cf.verified_bot_category in {…}`.
- **Default categories:**
  - search → `"Search Engine Crawler"`, `"AI Search"`
  - agent → `"AI Assistant"`
  - training → `"AI Crawler"`

  These can be changed with `category_overrides`.
- **How `allow` works:** it is implemented as `skip` with `ruleset = current`. That skips only the rest of the custom ruleset. Rate limits and managed rules still apply to the bot.
- **Scope:** verified bots only. An undeclared AI crawler has no category and is unaffected (the zones layer's `ai_bots_protection` handles those).
- **Labels:** `Bot traffic - <behaviour> (<action>)`.
- **Plan gate:** zone tier must be at least `bot_traffic_min_tier`.

### 3.2 Baseline custom rules (`http_request_firewall_custom`), all enabled

| Key | Dashboard name | Expression | Action | Requires |
|---|---|---|---|---|
| `block_admin_from_untrusted` | Baseline - restrict admin paths to trusted networks | `(path contains <each admin path>) and not ip.src in {trusted}` | block | Trusted IPs set |
| `geoblock_countries` | Baseline - block disallowed countries | `ip.geoip.country in {countries}` | block | Countries set |
| `block_listed_ips` | Baseline - block addresses on the account IP blocklist | `ip.src in $<list_name>` | block | `waf_ip_blocklist_name` set. The list is created by the `lists` layer (applied first) and its entries are managed outside Terraform, so an incident block needs no pipeline run |
| `block_known_exploit_paths` | Baseline - block probes for common exploit paths | path contains `/.env`, `/.git/`, `/vendor/phpunit` or `/.aws/`, or path eq `/.DS_Store` | block | None |
| `challenge_undisclosed_bots` | Baseline - challenge unverified automated traffic | `cf.client.bot eq false and cf.threat_score gt 14 and not ip.src in {trusted}` | managed_challenge | Trusted IPs set (see issue 2) |
| `log_trusted_admin_access` | Baseline - log admin access from trusted networks | `(admin paths) and ip.src in {trusted}` | log | Trusted IPs set. Audit companion to `block_admin_from_untrusted` |

### 3.3 Baseline rate limits (`http_ratelimit`)

Every rule counts on `ip.src` + `cf.colo.id`.

| Key | Name | Match | Threshold | Action / timeout | Notes |
|---|---|---|---|---|---|
| `auth_brute_force` | Baseline - authentication brute force | path contains `/login` or `/auth` | 20 req / 60 s | block / 600 s | |
| `api_general` | Baseline - general API ceiling | `starts_with(path, "/api/")` | 600 / 60 s | managed_challenge / 60 s | |
| `origin_error_shield` | Baseline - back off when origin is failing | not `/healthz*` | 50 / 60 s | block / 60 s | Counts only `http.response.code ge 500` (`requests_to_origin = true`). Protects an origin while it recovers |
| `observe_only` | Baseline - observe request rates without enforcing | not `/healthz*` | 1000 / 60 s | log / timeout forced to 0 | Used to size a limit before enforcing one |

### 3.4 Managed rulesets (`http_request_firewall_managed`)

Both execute on all zone traffic (`expression = true`) at the latest version.

- **`cloudflare_managed`**: Cloudflare Managed Ruleset, ID `efb7b8c949ac4650a09736fc376e9aee`. The only override is the action, from `waf_managed_rules_action` (null = Cloudflare's shipped per-rule actions).
- **`owasp_core`**: Cloudflare OWASP Core Ruleset, ID `4814384a9e5d4991b9815dcfc25d2f1f`.
  - Paranoia-level categories above the configured PL are disabled (default PL1, so PL2–4 are off).
  - The anomaly rule `6179ae15870a4bb7b2d480d4843b323c` is overridden with `score_threshold = 40` and `action = waf_owasp_action`.
- **Tenant additions:** extra managed rulesets (for example WordPress or Drupal) can be added per policy by raw ID through `managed_rulesets`.
- **Plan gate:** zone tier must be at least `managed_rules_min_tier`.
- Free zones already have Cloudflare's Free Managed Ruleset applied by Cloudflare. It is not managed here.

### 3.5 Managed exception: `html_submission`

- **Name:** "Baseline - HTML submission routes skip HTML injection signatures".
- **Expression:** `http.host in {<policy hostnames>} and (http.request.method in {methods} and http.request.uri.path matches "^(p1|p2…)$")`.
- **What it skips:** the whole OWASP verdict (the anomaly rule), plus only the listed Cloudflare Managed rule IDs. The rest of the Cloudflare Managed ruleset keeps running.
- **Narrowing:** it only skips rulesets that the policy actually executes.
- **Logging:** always on.
- **Hostnames:** required. Must be lowercase FQDNs, no wildcards.
- **Plan requirement:** the `matches` operator needs Business or above.

## 4. Plan-time guardrails (preconditions)

The plan fails when:

- a `zone_key` is missing from the zones inventory;
- a baseline rule name is unknown (the error lists the valid names);
- a baseline rule is selected while the variable it depends on is empty (trusted IPs, countries, blocklist name, HTML paths/methods);
- an exception has nothing to skip;
- a policy uses managed rulesets on a zone below `managed_rules_min_tier`;
- a policy uses `bot_traffic` on a zone below `bot_traffic_min_tier`;
- two rules in a ruleset share a label;
- a bot category override is an empty list.

Input validation also checks:

- IPs/CIDRs are valid;
- country codes are uppercase alpha-2;
- admin paths start with `/` and contain no quotes;
- HTML paths are valid regexes with no quotes or backslashes;
- rule IDs are 32 hex characters;
- the list name matches `^[a-z0-9_]{1,50}$`.

## 5. Tenant extension points

- **`custom_block_rules`**: actions block, challenge, managed_challenge, js_challenge, log or skip. A skip takes `ruleset`, `rulesets`, `phases` or `products`, plus optional logging.
- **`rate_limiting_rules`**
- **`managed_rulesets`** (by raw ID)
- **`managed_exceptions`**
- **Ruleset display names**

A skip in custom rules can only drop the whole managed phase. Granular exclusions go in `managed_exceptions`. Tenant rules run after the baseline, so a tenant skip cannot undo a baseline block that has already fired.

## 7. Related controls outside the WAF layer

- **Zone TLS defaults:** SSL `strict`, minimum TLS 1.2, TLS 1.3 on without 0-RTT, Always Use HTTPS on. account_a `primary` overrides SSL to `full`.
- **Security level:** `security_level = medium` by default.
- **Bot management:** `default_bot_management = null`, so zone bot settings are left as they are unless set.
- **IP list:** account_a's lists layer creates `yourorg_global_ip_blocklist` (kind ip, entries managed outside Terraform).
- **Turnstile:** a separate layer provides Turnstile widgets.
- **Not configured anywhere in the repo:** leaked-credential detection, API Shield/schema validation, Page Shield (only its log dataset appears in Logpush), DDoS ruleset overrides, Advanced Rate Limiting, Enterprise Bot Management score rules, Firewall for AI. The HLD should list these as out of scope or future work.

## 8. Known issues / open items

Flag these in the HLD; do not treat them as design intent.

1. **Managed-rules plan gate disagrees with itself.** `defaults.auto.tfvars` sets `managed_rules_min_tier = "enterprise"`, but the variable default, its description and the precondition error message all say Pro. Because of this, **account_a `primary` (Business) fails preflight** as committed.
2. **`challenge_undisclosed_bots` depends on `cf.threat_score`.** Cloudflare deprecated this field and it now always returns 0. So `gt 14` never matches, and the rule does nothing. Cloudflare also signalled it would disable threat-score rules after Q1 2026.
3. **Rate-limit plan limits are not checked at plan time.** Every baseline rule uses a 60 s period. Free plans allow only 10 s and 1 rule; Pro allows up to 1 min and 2 rules. Counting expressions (`origin_error_shield`) need Business or above. So account_b's `observe_only` on a Free zone is likely to fail at apply.
4. **account_a's blocklist is never used.** It creates `yourorg_global_ip_blocklist`, but `waf_ip_blocklist_name` is unset and `block_listed_ips` is not selected.
5. **account_a sets blocked countries but never selects `geoblock_countries`** (see section 6).
6. **The admin-path list blocks public login pages.** It includes `/user/login`, `/user/password` and `/user/register`, so any public site loses these for untrusted IPs (a code comment acknowledges this). `contains` is also broad: `/admin` matches `/administrator` and `/blog/admin-tips`.
